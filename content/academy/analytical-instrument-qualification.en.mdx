# Analytical Instrument Qualification (USP &lt;1058&gt;)

Analytical Instrument Qualification (AIQ) is the collection of documented
evidence that an instrument performs suitably for its intended purpose. USP
general chapter &lt;1058&gt; is the governing reference. Its central idea is the
data-quality triangle: every reported result rests on four layers, and AIQ is
the base layer.

| Layer | Question it answers |
| --- | --- |
| Analytical Instrument Qualification | Is the instrument fit for its intended use? |
| Analytical Method Validation | Is the method fit for its intended purpose on a qualified instrument? |
| System Suitability Tests | Is the instrument-method combination performing acceptably today? |
| Quality Control Check Samples | Is the whole system in control over time? |

The practical consequence: system suitability passing today does not rescue an
instrument that was never qualified, and method validation on an unqualified
instrument is built on sand. Qualification scope should be risk-based: USP
&lt;1058&gt; itself states that the extent of qualification depends on the
complexity and intended use of the instrument.

## The 4Qs applied to instruments

| Stage | Content for analytical instruments | Usually executed by |
| --- | --- | --- |
| DQ - Design Qualification | Functional and operational specifications for the intended use; vendor selection; fitness-for-purpose assessment | Lab defines requirements; vendor supplies specification evidence |
| IQ - Installation Qualification | Correct delivery, site/environment suitability, installation per vendor spec, software installation, network and power checks | Vendor engineer, witnessed/reviewed by the lab |
| OQ - Operational Qualification | Instrument functions to vendor specification across operating ranges: detector linearity, wavelength accuracy, flow precision, temperature accuracy, as applicable | Often vendor test scripts executed on site; lab reviews, approves, and owns the outcome |
| PQ - Performance Qualification | Fit for actual routine use: method-relevant checks, calibration, preventive maintenance, performance verification, change control | The laboratory |

Note the role split. DQ and OQ lean heavily on vendor knowledge; IQ is a shared
activity; PQ is unambiguously the lab's job because only the lab knows the
routine methods, sample matrices, and usage patterns. USP &lt;1058&gt; is
explicit that the user has ultimate responsibility for the instrument's
qualification and data quality regardless of who turns the wrenches.

## Risk-based instrument groups

USP &lt;1058&gt; classifies instruments into three groups by complexity and
measurement role. The group determines the qualification effort.

| Group | Description | Examples | Typical qualification |
| --- | --- | --- | --- |
| A | Standard apparatus with no measurement capability or user calibration | Magnetic stirrers, vortex mixers, non-measuring hot plates | Conformance to requirement observed and documented; no formal qualification |
| B | Standard equipment providing measured values or controlling a parameter; user calibratable | Balances, pH meters, thermometers, ovens, refrigerators, pipettes | IQ plus OQ largely covered by routine calibration and performance checks against specifications; standard SOPs suffice for much of it |
| C | Computerized analytical instruments where software and instrument combine to produce the result | HPLC/UPLC, GC, GC-MS, LC-MS, UV-Vis spectrophotometers, dissolution baths with control software, TOC analyzers | Full 4Qs: vendor firmware plus application software, configuration, access control, audit trail, and data-management verification |

Misclassification is a real audit topic. A "simple" UV spectrophotometer with
embedded control software and data storage is Group C. A balance with a
metrology-controlled weighing application feeding a LIMS may also drift toward
Group C treatment for its software layer.

## What OQ testing actually covers

For a Group C instrument such as an HPLC, OQ demonstrates, against documented
acceptance criteria, functions such as:

- pump flow-rate accuracy and composition precision;
- autosampler injection precision and carryover;
- column-oven temperature accuracy and stability;
- detector wavelength accuracy and linearity (UV), or mass accuracy and
  resolution (MS);
- system noise and drift within specification.

Vendor OQ packages are widely used and acceptable, provided the site reviews
the protocols, confirms the acceptance criteria fit the intended use, and keeps
raw data and certificates retrievable. The vendor cannot approve your
qualification: review, deviation closure, and final sign-off belong to the user
and QA.

## Software and data integrity

For Group C instruments, the software is part of the instrument. Qualification
should cover:

- installed software/firmware versions recorded as a configuration baseline;
- user access levels, unique accounts, and password controls verified;
- audit trail enabled and generating reviewable entries;
- time and date functions controlled;
- backup, restore, and archive demonstrated at least once;
- electronic records requirements (21 CFR Part 11 or EU Annex 11) assessed
  where the data are GMP records.

Firmware that cannot be configured by the user is generally qualified as part of
the instrument; the application software layer (chromatography data systems,
LIMS interfaces) typically also falls under the site's computer-system
validation program.

## Maintaining the qualified state

Qualification decays. The maintained state for an analytical instrument is
built from:

- periodic calibration against traceable reference standards (for example
  balance weights traceable to national standards);
- preventive maintenance per vendor schedule, documented;
- periodic performance verification / requalification at a justified interval
  (industry practice commonly uses 6 or 12 months for Group C workhorses, with
  the interval justified by usage and drift history);
- change control for software updates, firmware patches, component
  replacements, relocations, and repairs;
- logbooks linking every use, maintenance event, and calibration to the
  instrument's history.

Requalification triggers include relocation, major repair (lamp, pump seals,
detector, board replacement), software or firmware change, out-of-calibration
events, and adverse trends in calibration or check-sample data.

## Common GMP findings

- Instruments in routine use with no qualification file, or only a vendor
  invoice and manual.
- Vendor OQ certificates filed without site review or approval.
- Group A/B/C classification never performed, so a pH meter and an LC-MS
  receive identical treatment.
- Software versions unrecorded; updates installed informally with no change
  control or impact assessment.
- Audit trails never verified as part of qualification, then never reviewed in
  routine use.
- Calibration and qualification confused: a calibrated instrument is not
  automatically a qualified instrument, and vice versa.
- Requalification skipped after relocation or major repair.
- Acceptance criteria copied from vendor defaults that do not match the site's
  intended use.

## Documentation checklist

- user requirement / intended-use statement;
- risk-based group classification with rationale;
- DQ evidence (specification review, vendor assessment);
- IQ protocol and report with environment, installation, and software checks;
- OQ raw data, certificates, and reviewed report;
- PQ/performance-verification plan tied to actual methods;
- calibration and preventive-maintenance schedules;
- software configuration baseline and data-integrity assessment;
- change-control and periodic-review linkage.
